# Decisions

Format: date, decision, why, tradeoff. Fallbacks taken are marked FALLBACK.

- 2026-11-08: TypeScript pinned to 6.0.3, not 7.0. typescript-eslint 8.72 supports TS below 6.1 only, and typed lint rules are a quality gate. Tradeoff: we skip the faster native compiler.
- 2026-11-08: Workspace packages export TypeScript source (no per-package build) except `@ferry/sdk`, which is published. Bundlers (Next.js, WXT, Vercel) compile them. Tradeoff: consumers must use a bundler, which every Ferry surface does.
- 2026-11-08: Memory header uses the PRD format with `s=` as a comma list, so one memory can carry merged receipts ("heard in ChatGPT and Claude"). Fact text is NFKC normalized and stripped of the header brackets before encoding, so no fact can forge a header.
- 2026-11-08: Extension messages are split into ContentRequest, PanelRequest and WebAppRequest. The worker picks the schema from `sender`, never from the payload, so a content script can never call wipe, hide or settings.
- 2026-11-08: Delegate key is an extractable 32-byte Ed25519 seed, not a non-extractable WebCrypto key. The MemWal SDK signs SEAL session keys with `Ed25519Keypair.fromSecretKey(seed)` and needs raw bytes (RESEARCH 1.4). Control: the seed is encrypted at rest with AES-GCM under a PBKDF2-SHA256 (600k iterations) key from the user passphrase, decrypted only in the service worker, cached in `chrome.storage.session` with access level TRUSTED_CONTEXTS so content scripts cannot read it, and cleared on auto-lock.
- 2026-11-08: The extension is the memory engine for every surface. The relayer sends no CORS allow-origin (RESEARCH 1.7, still relayer 0.1.0), and putting a delegate key on a Ferry server would break "no Ferry server sees memory traffic". The web app reaches memory through `externally_connectable` limited to the Ferry origin; WebAppRequest widened to recall, list, save, hide, resolve and export. Wipe and settings stay side-panel only.
- 2026-11-08: Writes always go through `rememberBulk` with up to 20 items (10 points per call versus 5 per single remember) and a client token bucket under the real limits: 30 points per minute per key, 60 per minute and 500 per hour per account (RESEARCH 1.2). The PRD's "about 24 per minute" figure was wrong.
- 2026-11-08: Onboarding uses the relayer's sponsored gas endpoints for create_account and add_delegate_key when they work, so a new user needs no SUI. Falls back to a normal wallet-paid transaction.
- 2026-11-09: Importers reject the whole ZIP on any unsafe entry name (`..`, absolute, backslash, drive letter) instead of skipping it, since no vendor export contains one. Limits are measured on bytes actually inflated; central-directory uncompressed sizes are ignored. Entry cap is 20,000 (brief) not 50,000 (threat model): the stricter wins.
- 2026-11-08: pnpm minimumReleaseAge exclusions accepted for the AI SDK 7.0.165 family (published within the release-age window). They are first-party Vercel packages, pinned exactly, and lockfile-verified. Everything else respects the release-age gate. The memwal engineer pinned fake-indexeddb to 6.2.5 instead of excluding 6.2.8.
- 2026-11-08: FALLBACK apps/web builds with webpack (next build --webpack) plus resolve.extensionAlias, because Turbopack in Next 16.4.5 does not resolve '.js' specifiers that point at '.ts' sources in workspace packages. Tradeoff: slower dev rebuilds; no runtime difference.
- 2026-11-09: `Mppx` (server) is imported from `mppx/server`, not `mppx` as RESEARCH 4.3 shows; verified in `mppx@0.4.12` dist. The suimpp `DigestStore` is has-then-set, a read-then-write, so the Gate builds a store per request whose `set` is the atomic insert into `payments` (UNIQUE digest and UNIQUE challenge_id), carrying card, payer, amount and query hash. `has` is only a fast path. Tradeoff: one mppx instance per request (no I/O, cheap).
- 2026-11-09: Challenges are both HMAC-bound by mppx and stored in Neon (X-PAY-2); a stored challenge is consumed by the payments row's UNIQUE(challenge_id), so the same insert enforces single use. Tradeoff: one write per 402, bounded by the per-IP limit.
- 2026-11-09: The suimpp server method checks the chain itself through the public fullnode (gRPC-Web cannot reach Tatum, RESEARCH 4.3). The Gate runs its own Tatum verification first, through `@ferry/chain` verifyUsdcPayment, so both must agree before anything is served. x402 payer-signed bytes are executed on the public fullnode and the result is then re-verified through Tatum inside `DigestStore.set`.
- 2026-11-09: `GET /v1/earnings?owner=` requires the owner's SIWS session. Query hashes are not on chain and short queries are guessable from a SHA-256, so they are private to the card owner. Card creation requires the session address to equal `GATE_PUBLIC_ACCOUNT_OWNER`, otherwise anyone could sell the Public profile account's facts to their own address.
- 2026-11-09: The Gate serves every fact in `ferry-public` that carries a valid active Ferry header; per-card fact selection is not stored in Neon (no memory references there). Cards differ by name, scope, price, cap and allowed agents. If per-card selection is needed, use one Public profile account per card.
- 2026-11-09: If recall fails after a payment committed, the Gate answers 502 with the receipt id and digest instead of serving nothing silently. There is no automatic refund. Accepted for the hackathon; the receipt makes the case visible in Earnings.
- 2026-11-08: mppx 0.4.12 advisories GHSA-727h-3vm5-qwq6 and GHSA-vc9j-9wph-qghj ignored in osv-scanner.toml until 2026-12-31: they affect the EVM fee-payer path, which Ferry never uses (Sui method, Gate never pays gas). Upgrade blocked by @suimpp/mpp pinning mppx ^0.4.9.
