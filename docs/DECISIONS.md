# Decisions

Format: date, decision, why, tradeoff. Fallbacks taken are marked FALLBACK.

- 2026-11-08: TypeScript pinned to 6.0.3, not 7.0. typescript-eslint 8.72 supports TS below 6.1 only, and typed lint rules are a quality gate. Tradeoff: we skip the faster native compiler.
- 2026-11-08: Workspace packages export TypeScript source (no per-package build) except `@ferry/sdk`, which is published. Bundlers (Next.js, WXT, Vercel) compile them. Tradeoff: consumers must use a bundler, which every Ferry surface does.
- 2026-11-08: Memory header uses the PRD format with `s=` as a comma list, so one memory can carry merged receipts ("heard in ChatGPT and Claude"). Fact text is NFKC normalized and stripped of the header brackets before encoding, so no fact can forge a header.
- 2026-11-08: Extension messages are split into ContentRequest, PanelRequest and WebAppRequest. The worker picks the schema from `sender`, never from the payload, so a content script can never call wipe, hide or settings.
- 2026-11-08: Delegate key is an extractable 32-byte Ed25519 seed, not a non-extractable WebCrypto key. The MemWal SDK signs SEAL session keys with `Ed25519Keypair.fromSecretKey(seed)` and needs raw bytes (RESEARCH 1.4). Control: the seed is encrypted at rest with AES-GCM under a PBKDF2-SHA256 (600k iterations) key from the user passphrase, decrypted only in the service worker, cached in `chrome.storage.session` with access level TRUSTED_CONTEXTS so content scripts cannot read it, and cleared on auto-lock.
- 2026-11-08: The extension is the memory engine for every surface. The relayer sends no CORS allow-origin (RESEARCH 1.7, still relayer 0.1.0), and putting a delegate key on a Ferry server would break "no Ferry server sees memory traffic". The web app reaches memory through `externally_connectable` limited to the Ferry origin; WebAppRequest widened to recall, list, save, hide, resolve and export. Wipe and settings stay side-panel only.
- 2026-11-08: Writes always go through `rememberBulk` with up to 20 items (10 points per call versus 5 per single remember) and a client token bucket under the real limits: 30 points per minute per key, 60 per minute and 500 per hour per account (RESEARCH 1.2). The PRD's "about 24 per minute" figure was wrong.
- 2026-11-08: Onboarding uses the relayer's sponsored gas endpoints for create_account and add_delegate_key when they work, so a new user needs no SUI. Falls back to a normal wallet-paid transaction.
- 2026-11-09: Importers reject the whole ZIP on any unsafe entry name (`..`, absolute, backslash, drive letter) instead of skipping it, since no vendor export contains one. Limits are measured on bytes actually inflated; central-directory uncompressed sizes are ignored. Entry cap is 20,000 (brief) not 50,000 (threat model): the stricter wins.
- 2026-11-08: pnpm minimumReleaseAge exclusions accepted for the AI SDK 7.0.165 family (published within the release-age window). They are first-party Vercel packages, pinned exactly, and lockfile-verified. Everything else respects the release-age gate. The memwal engineer pinned fake-indexeddb to 6.2.5 instead of excluding 6.2.8.
- 2026-11-08: FALLBACK apps/web builds with webpack (next build --webpack) plus resolve.extensionAlias, because Turbopack in Next 16.4.5 does not resolve '.js' specifiers that point at '.ts' sources in workspace packages. Tradeoff: slower dev rebuilds; no runtime difference.
- 2026-11-09: `Mppx` (server) is imported from `mppx/server`, not `mppx` as RESEARCH 4.3 shows; verified in `mppx@0.4.12` dist. The suimpp `DigestStore` is has-then-set, a read-then-write, so the Gate builds a store per request whose `set` is the atomic insert into `payments` (UNIQUE digest and UNIQUE challenge_id), carrying card, payer, amount and query hash. `has` is only a fast path. Tradeoff: one mppx instance per request (no I/O, cheap).
- 2026-11-09: Challenges are both HMAC-bound by mppx and stored in Neon (X-PAY-2); a stored challenge is consumed by the payments row's UNIQUE(challenge_id), so the same insert enforces single use. Tradeoff: one write per 402, bounded by the per-IP limit.
- 2026-11-09: The suimpp server method checks the chain itself through the public fullnode (gRPC-Web cannot reach Tatum, RESEARCH 4.3). The Gate runs its own Tatum verification first, through `@ferry/chain` verifyUsdcPayment, so both must agree before anything is served. x402 payer-signed bytes are executed on the public fullnode and the result is then re-verified through Tatum inside `DigestStore.set`.
- 2026-11-09: `GET /v1/earnings?owner=` requires the owner's SIWS session. Query hashes are not on chain and short queries are guessable from a SHA-256, so they are private to the card owner. Card creation requires the session address to equal `GATE_PUBLIC_ACCOUNT_OWNER`, otherwise anyone could sell the Public profile account's facts to their own address.
- 2026-11-09: The Gate serves every fact in `ferry-public` that carries a valid active Ferry header; per-card fact selection is not stored in Neon (no memory references there). Cards differ by name, scope, price, cap and allowed agents. If per-card selection is needed, use one Public profile account per card.
- 2026-11-09: If recall fails after a payment committed, the Gate answers 502 with the receipt id and digest instead of serving nothing silently. There is no automatic refund. Accepted for the hackathon; the receipt makes the case visible in Earnings.
- 2026-11-08: mppx 0.4.12 advisories GHSA-727h-3vm5-qwq6 and GHSA-vc9j-9wph-qghj ignored in osv-scanner.toml until 2026-12-31: they affect the EVM fee-payer path, which Ferry never uses (Sui method, Gate never pays gas). Upgrade blocked by @suimpp/mpp pinning mppx ^0.4.9.
- 2026-11-08: Public profile account created with a locally generated owner key (user chose this). Owner 0x53ec2bc08e0b15040c0e6863cb175ee66428d64f9e6ac5c7480bd6efe5d3f73b, account 0x3a75eca8c67b7f70a7a2de8cdc7d8fb85137e3231c6023fc555e37e3ec4cfe8f, create_account tx Hih5RG5uqiyZ85dEDaHqKTAKVrpTCNPTJx9pKBNDJQjs, add_delegate_key tx 2Ra4iESUsJwdQBMdbqtfN3ue4r2dZv7j9ryfyejLtfZY, both on relayer-sponsored gas. The setup script reads through the public fullnode because no Tatum key existed yet; product reads go through Tatum.
- 2026-11-08: FALLBACK Gate ships as an esbuild bundle (apps/gate/api/index.mjs) with web-standard GET/POST/PATCH/OPTIONS exports, because Vercel's Node runtime neither compiles nor traces workspace packages that export TypeScript sources (ERR_MODULE_NOT_FOUND on @ferry/core/src/index.ts).
- 2026-11-09: Extension response shapes are frozen in @ferry/core (`WebAppResponse`, `PanelResponse`, one zod schema per request type). The worker parses its own reply with the schema before sending, so a drifted shape fails as `internal` in the extension instead of half-rendering in the web app, and `apps/web/src/lib/bridge.ts` parses again on receipt. The ad hoc shapes in `apps/extension/src/lib/protocol.ts`, `worker/ports.ts` and the old bridge mirrors are gone. `memory.recall` returns a bare `Suggestion[]`; saves return `SaveResult` (the memwal `FactWriteResult` discriminant `status` plus `merged` and `conflict`); a Library conflict rides on the stored memory it disputes, with the held fact's candidate id as `otherRef`, so `keep_new` and `merge` always supersede the item's own ref. The web app's status omits adapter health and unsaved capture text. Tradeoff: one extra zod parse per response.
- 2026-11-09: The extension id is pinned with a manifest `key` (RSA 2048, public half in `apps/extension/manifest.config.ts`, private half in `apps/extension/.extension-key.pem`, gitignored and path-allowlisted in `.gitleaks.toml` so `--no-git` scans stay clean). Id `opikbjojfgmdadhaljejplogjppfkhoh` is the web default and is always accepted by the chain proxy CORS. Tradeoff: the key is public by design, so a modified unpacked build gets the same id; the web app still trusts nothing from the extension without a schema.
- 2026-11-09: One extension build accepts two web origins: `http://localhost:3000` and `FERRY_WEB_ORIGIN_PROD` (https only, build time), in `externally_connectable`, host permissions and the worker's exact-origin check. The API defaults to the production origin when set. Tradeoff: a release build also trusts whatever serves localhost:3000 on the user's machine, which could read memory through the web app channel. Accepted for the hackathon demo; a store build should drop the local origin.
- 2026-11-09: Publishing to the Public profile account is a CLI (`pnpm publish-public <file>`, scripts/publish-public.ts) using the Gate's own delegate key, not an extension request: the browser holds only the private account's key, and a second paired key is out of scope tonight. The Share page exports exactly the facts the user ticks (`PublishableFact[]`), the script screens each again and refuses anything not plainly safe, and writes with `c=` and `q=` set to the constant `ferry-public-redacted` so a published fact cannot be linked to a private conversation.
- 2026-11-09: Share and Earn uses the real Gate API: SIWS through `/v1/auth/nonce` and `/v1/auth/session` (wallet `signPersonalMessage`), cards through `/v1/manage/cards`, earnings through `/v1/earnings?owner=`. Sessions stay in memory only (4 hours). The page refuses to sign if the Gate's SIWS domain is not the page's host. New `GET /v1/profile` exposes the Public profile owner (already public as the payment recipient) so the page says up front that only that wallet may create cards. Response schemas (`GateNonce`, `GateSession`, `GateOwnerCard`, `GateEarnings`, `GateProfile`) live in core and the Gate tests parse with them.
- 2026-11-09: Landing and Proofs counters are real or null. `paidRecalls` is `count(*)` of Gate `payments` (each Tatum verified). `memories` is the last value `pnpm count-memories` wrote to Neon `public_stats` (migration 0002, numbers and a timestamp only), counted from `listMemories` metadata of the main account's `ferry-core` with no text read; tombstones count as stored records. Cached 60 s per instance. Tradeoff: the memory count is as fresh as the last script run.
- 2026-11-09: `pnpm build` for the Gate runs the Vercel Build Output bundle (`node scripts/bundle.mjs`), the artifact that actually deploys; the interim tsup build was removed so there is one build path.
- 2026-11-08: Release extension builds set FERRY_RELEASE=1, which drops http://localhost:3000 from externally_connectable and host permissions, so a shipped ZIP never trusts whatever serves localhost on a user's machine. Dev builds keep localhost.
- 2026-11-08: Slush's site scanner flags ferry-memory.vercel.app as malicious (heuristic on new vercel.app subdomains requesting wallet connections; the domain is not on MystenLabs/wallet_blocklist). Pairing is done from http://localhost:3000 (dev extension build trusts both origins). Follow-up: request review / allowlist, or move to a custom domain before submission.
- 2026-11-09: Side panel Now tab mirrors the chat tab's own `recall.suggest` instead of recalling again: new PanelRequest `now.suggestions` reads the worker's per-tab cache (no relayer points), and `now.insert` messages that tab's content script, which composes through the same `inject.compose` path as the chip. The worker checks the refs against what the tab was shown before messaging it, and the content script's compose checks them again. Core additions are additive (`TabId`, `NowSuggestions`, `NowInserted`, PanelResponse entries) with tests. Tradeoff: the panel lists nothing until the user has typed in the chat for 600 ms; that is the PRD F3 trigger, so it is the honest state.
- 2026-11-09: F10 Vault mode is wired in the extension, not marked unavailable. A wallet signer cannot run in the extension (Wallet Standard wallets inject only into web pages), but `memwal::account::seal_approve` accepts any registered delegate, and the MemWal SDK itself signs its Seal sessions with the delegate key. So the Vault engine passes the delegate seed as `suiPrivateKey` (`manualSignerConfig` in packages/memwal vault.ts) and there is no wallet popup at all. DESIGN 9.4 updated: it said "one wallet approval per session" (not true here) and "encrypted vectors" (vectors are not encrypted). Tradeoff: the delegate key that already reads the whole account also opens Seal shares, which adds no new authority; removing the device revokes both.
- 2026-11-09: Vault switches only new writes. `SplitPort` sends saves and new imports to `FerryVaultMemory`, while recall, Library, hide, conflicts and export span both engines; imports queued before the switch finish in Standard. Both engines share one RateGovernor (one key budget). The BYOK embedding key is sealed at rest with AES-GCM under an HKDF key from the delegate seed (`sealSecret`, purpose `vault.embedding`), so it opens only while Ferry is open; panel-only messages (`vault.status`, `vault.enable`, `vault.disable`), and `vault.disable` deletes the sealed key. Enabling rebuilds the engine at once, so a bad key or a non-1536 model fails in Settings and Standard stays on. Not yet verified live: needs a real embedding key and a paired account. Known gap: the F5 neighbor check for a new Vault fact only sees Vault memories.
- 2026-11-09: F9 encrypted backup uploads through `@mysten/walrus` with the public upload relay (`upload-relay.mainnet.walrus.space`, tip capped at 1,000,000 MIST), not Tatum Storage: its upload endpoint needs a Tatum API key and Ferry has none to put in a browser. Seal identity reuses the MemWal policy with prefix `ferry-backup` (namespace, owner, u64 counter, the SDK's layout), counter read fresh from chain before each backup. The ZIP is wrapped in a small envelope (`FERRYBK1`, header JSON, bytes) so restore returns the original name. The user's wallet pays WAL and gas; nothing here was run on Mainnet (no funds spent). CSP on `/settings` only adds the two Seal key servers, the relay and `'wasm-unsafe-eval'` for the Walrus encoder. Backup records live in this browser's localStorage; the Blob objects stay in the wallet. Unit tests cover the pure parts; the wallet flow is not in CI.
- 2026-11-09: Root font size: `:root { font-size: 0.875rem }` in tokens.css was a bug, not intentional density. It made 1rem 14px, so every token and the spacing grid rendered at 87.5 percent and micro text fell under 11px. The 14px UI base moved to `body` and `:host`; DESIGN 2.3 records it. Landing prose is `body-lg`, 16px rendered.
- 2026-11-09: Landing performance: the web app serves a cut of Bricolage Grotesque (wght 600, wdth 92 to 94, opsz 24 to 96, Latin, 50 KB instead of 129 KB, fontTools instancer, OFL text alongside) and Geist Latin from `public/fonts`, both preloaded on `/` only. The extension keeps the full Fontsource files. Next `experimental.inlineCss` was tried and reverted: the inlined style tag has no CSP nonce, so the policy blocks it.
